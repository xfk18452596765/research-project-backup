# 交付丢失边界诊断

## 方法

参考程序运行于 ns-3.43，数据包实际穿过 UDP socket、IPv4、`AdhocWifiMac` 和
`YansWifiPhy`。`DiagnosticTag` 在栈内携带 `(seq, hop)`，trace 记录：

`APP_CREATE → APP_SEND_ATTEMPT → SOCKET_SEND_ACCEPTED → MAC_ENQUEUE → PHY_TX →
PHY_RX/PHY_RX_DROP → UDP_RX → TERMINAL`。

每包只保留一个最终终态，守恒检查为：

```text
created = DELIVERED + 所有最终损失
UNKNOWN_LOSS = 0
```

没有足够证据细分到 Wi-Fi 内部 retry exhaustion 的包归入
`SIMULATION_STOP_TIMEOUT`，而不是伪造为 `MAC_RETRY_EXHAUSTED`。因此终态完整，
但 `SIMULATION_STOP_TIMEOUT` 仍表示需要更深的原生 MAC retry trace。

## 高负载定位结果

每格聚合 6 次运行（periodic/poisson × seeds 7/17/27），每次 100 包、6 hop。

| mode | DCF 交付率 | Fixed 交付率 | 诊断含义 |
|---|---:|---:|---|
| original | 27.33% | 18.33% | 复现 Fixed 明显更差 |
| causal-forwarding | 3.00% | 16.83% | 因果门控暴露真实端到端连乘，原预调度会虚增终点交付 |
| positioned-chain | 79.17% | 65.17% | 单独修正全连接拓扑显著改善两者，确认强实现伪影 |
| k2-segment | 27.33% | 39.17% | K=2 减少 Fixed 控制竞争；DCF 不变 |
| reservation-window | 27.33% | 17.50% | 仅应用层错峰不能形成真正 MAC 保护，未改善 |
| combined-reference | 35.67% | 23.67% | 组合语义仍有 Fixed 相对损失，协议风险残留 |

原 Fixed 高负载 600 包中，110 包交付、86 包在可关联的 PHY 接收丢失边界结束，
404 包在仿真停止时仍无终点 UDP 接收。组合参考中 Fixed 为 142 交付、37 个
PHY_RX_DROP、421 个 SIMULATION_STOP_TIMEOUT。所有模式 `UNKNOWN_LOSS=0`。

低负载门禁先于高负载运行：单包 8/8 运行全部交付，十包低负载
108/108 运行全部交付。
