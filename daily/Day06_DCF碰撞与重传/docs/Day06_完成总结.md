# Day06：DCF碰撞与重传完成总结

## 一、今日目标

在Day05信道忙检测与退避冻结机制基础上，实现两个节点同时竞争信道时的碰撞、ACK超时、二进制指数退避和数据包重传。

## 二、已完成内容

1. 实现双节点共享碰撞域；
2. 实现同一时隙发送请求的统一判定；
3. 实现DATA帧碰撞；
4. 实现碰撞后不返回ACK；
5. 实现ACK超时事件；
6. 实现数据包重传次数增加；
7. 实现竞争窗口从15扩大到31；
8. 实现重传后的重新竞争；
9. 实现竞争过程中退避冻结与恢复；
10. 实现有限重传次数和超过上限后的丢包；
11. 完成自动测试；
12. 完成双节点碰撞主程序验证。

## 三、核心事件链

PACKET_ARRIVAL
→ DIFS
→ BACKOFF
→ 同槽TX_START
→ COLLISION
→ TX_END
→ ACK_TIMEOUT
→ CW_UPDATE
→ DIFS
→ BACKOFF
→ 重传
→ ACK
→ DELIVERED

## 四、运行结果

首次竞争时：

- 节点0退避槽数：0；
- 节点1退避槽数：0；
- 碰撞次数：1。

碰撞后：

- 两个数据包重传次数均为1；
- 两个节点的CW均由15增加到31。

第一次重传：

- 节点0退避槽数为0，先成功发送；
- 节点1退避槽数为1，在节点0发送期间冻结。

最终：

- 两个数据包均成功送达；
- 成功传输次数为2；
- 信道恢复空闲；
- 两个节点MAC状态均恢复IDLE；
- 数据包送达率为1.000。

## 六、结论

Day06完成了传统DCF基线中的碰撞与重传核心机制，为后续多跳DCF逐跳竞争和端到端时延累计实验提供了基础。
