# 补丁链一致性结论

基线为 ns-3.43（官方 tag 所指的 `753817468d611239b1e3c2e272b2bed8ef1f580c`）。Git
对象恢复证明 P1、P2、P3 的权威 raw SHA-256 依次为
`90823ff0d2bc380ad838007293b87c87f3631c73b313b38b92d4da46907184db`、
`8c55571e688502973dfbde0eb0a3dd0289354a55c8550efbd3995f9c6195ab46`、
`3c0b444539d29ec5142c7293de23470fc9b54dc13d36d9f02d0752aedfcb0e84`。

对应 source commit/blob 分别为 `7560ac7/06bd703`、`aacc709/c0c94be`、
`5b5ef91/cb21f39`。P1 的历史 SHA 与 Git blob 完全匹配；P2 的错误历史字段引用
了 attribution-hold manifest 的 SHA；P3 的旧字段引用了 CRLF checkout SHA 或前一份
trace patch SHA。详细的 append-only 更正记录在 `results/manifests/patch_chain_erratum.json`。

所有当前 checkout 都是 CRLF、Git blob 都是 LF、无 BOM 且保留尾部换行；因此 checkout
SHA 的不同仅由换行规范化造成。

两份独立、临时的官方 ns-3.43 副本均在 P1 的 `git apply --check` 停止：权威 raw blob
在第 100 行报告 `corrupt patch`。没有修改 patch、没有忽略 hunk，也没有继续 P2/P3。
所以没有可比较的最终源码树 SHA，最终决定为 **PATCH_CHAIN_HOLD**（原因：
`SEMANTIC_PATCH_DIVERGENCE` 不适用；实际原因是 `CANONICAL_P1_PATCH_CORRUPT`）。
