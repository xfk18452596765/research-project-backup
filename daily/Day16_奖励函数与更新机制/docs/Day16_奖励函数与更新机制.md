# Day16：奖励函数与更新机制

## 1. 继承边界

Day16 严格继承已冻结设计：

- 技术主线保持 `DCF → Fixed-PRMAC → RL-PRMAC`；
- 决策主体仍是当前预约段起始节点；
- 决策仍发生在本地 FIFO 队首获得服务资格后、初始 DIFS/退避前；
- 动作仍为 `a=(K,CW)`，其中 `K∈{1,2,3}`、`CW∈{15,31}`；
- 一个动作覆盖完整预约段及其全部 PR_NACK/BEB 重试；
- Day14 状态接口、Day15 动作编号和节点独立稀疏 Q 表均不修改；
- 不引入中心控制、全网状态、未来端到端时延、逐跳重复决策或 PR_NACK 后重新决策。

## 2. 一次转移的生命周期

一次局部学习转移的起点是节点选择段级动作：

```text
本地 FIFO 队首开始服务
→ 编码 Day14 状态 s
→ 选择 Day15 动作 a=(K,CW)
→ 初始 DIFS/退避
→ 预约及可能的 PR_NACK/BEB 重试
→ 连续 DATA/H_ACK 转发
→ RELEASE 完成，或重试耗尽
→ 结算本段奖励 r
```

奖励严格对应一个完整预约段，而不是一跳。

### 下一状态的冻结语义

由于每个节点维护独立 Q 表，非终止转移中的 `s'` 定义为：

```text
同一个节点下一次成为预约段起始节点时的本地决策状态
```

而不是下游节点的私有状态。这样既保留 Bellman 更新，也不需要读取或共享其他节点的 Q 表、队列或信道状态。

当前段结算后，先保存 `(s,a,r)`；同一节点下一次出现决策时补齐 `s'`。若局部学习回合结束且没有下一决策，则生成终止转移，bootstrap 项为 0。

`packet_delivered` 只是当前段可本地确认的交付奖励，不自动等同于整个节点学习过程终止；是否终止由回合边界决定。

## 3. 本地奖励输入

奖励只使用当前节点或当前预约段可审计的信息：

- 当前 Day15 决策记录；
- 当前包优先级；
- 本地 FIFO 等待时延；
- 从动作选择到段成功/失败结算的服务时延；
- 段成功或失败；
- 本段实际推进跳数；
- 重试次数与 PR_NACK 次数；
- 当前段控制字节数；
- 数据载荷字节数；
- 当前段是否完成最终数据交付。

明确不使用：未来端到端时延、全网平均时延、全网队列、其他节点 Q 表、中心控制器输出。

## 4. 归一化

设：

- `p = clip(effective_hops / 3, 0, 1)`；
- `t = clip(segment_service_delay / 0.025, 0, 1)`；
- `q = clip(local_queue_delay / 0.050, 0, 1)`；
- `c = max(retries_used/retry_limit, pr_nack_count/(retry_limit+1))`，并裁剪到 `[0,1]`；
- `h = control_bytes/(control_bytes+payload_bytes)`；
- 普通业务的时延倍率 `m=1.0`，高优先级业务 `m=1.5`。

其中 25 ms 与 50 ms 是本地固定归一化尺度，不是从全局统计或未来数据计算得到。后续实验可以调参，但不得改变奖励的局部、多目标结构。

## 5. 冻结奖励公式

成功段的结果项为 `+1.00`，失败段为 `-1.25`。若当前段最终交付数据包，再加 `+0.35`。

```text
r_raw = outcome
      + 0.30 * p
      + 0.35 * delivered
      - m * (0.35 * t + 0.10 * q)
      - 0.25 * c
      - 0.10 * h

r = clip(r_raw, -2.0, 2.0)
```

设计含义：

- 成功/失败是主导项，防止只追求短时延却牺牲交付；
- 推进跳数给予有限正奖励，使长预约具有减少重复竞争的潜在收益，但不能无条件压倒冲突和开销；
- 服务时延、排队、重试和控制开销共同抑制不合适的 `(K,CW)`；
- 高优先级业务对时延更敏感，同等延迟下获得更低奖励，从而推动策略选择更低时延动作；
- 所有分量均归一化或裁剪，最终奖励也裁剪，避免量纲失衡和异常值破坏 Q 表。

## 6. Q-learning 更新

每个节点只更新自己的 `SparseLocalQTable`：

```text
Q(s,a) ← Q(s,a) + α [r + γ max Q(s',a') - Q(s,a)]
```

默认：

```text
α = 0.20
γ = 0.90
```

边界：

- `0 < α ≤ 1`；
- `0 ≤ γ ≤ 1`；
- 终止转移的 bootstrap 为 0；
- 非终止转移的 `max Q(s',a')` 只在 `next_remaining_hops` 对应的合法动作中计算；
- `K > remaining_hops` 继续报错，绝不静默截断；
- 学习器、转移和 Q 表的 `node_id` 必须一致；
- 不同节点不能共享同一个 Q 表。
