# Day13任务计划：Fixed-PRMAC验证与止损检查

## 一、今日唯一目标

1. 将Day09—Day12的单预约段能力组装为完整端到端Fixed-PRMAC；
2. 在2/4/6跳、低/中/高负载和多个随机种子下，与已锁定的Day08 DCF基线进行公平预比较；
3. 输出PASS、HOLD或FAIL止损结论；
4. 止损未通过前不进入Day14，不实现Q-learning。

## 二、端到端流程

```text
数据包到达
→ DIFS + CWmin随机退避
→ 当前段预约与PR_NACK重试
→ ACTIVE
→ DATA/H_ACK连续转发K跳
→ RELEASE
→ 当前节点发起下一预约段
→ 直到DELIVERED或重试耗尽DROPPED
```

固定参数保持：`K=2`、`CW_init=15`。

## 三、功能验证范围

- 2跳：1段；
- 4跳：2段；
- 6跳：3段；
- 奇数跳：最后一段自动截断；
- 冲突后重试成功；
- 持续冲突后重试耗尽；
- 多段预约ID、重试ID和转发ID互不串扰；
- 每段释放后再进入下一段；
- 最终交付时间与DCF统一到确认帧接收边界。

## 四、止损预实验范围

```text
协议：DCF、Fixed-PRMAC
跳数：2、4、6
负载：low=0.050s、medium=0.020s、high=0.008s
随机种子：7、17、27
每次运行：8个1024字节数据包
```

严格保持相同路由、包长、PHY速率、SIFS、DIFS、时隙、传播时延、CW范围、重试上限、负载和种子。

## 五、停止条件

- 完整回归失败；
- Fixed-PRMAC多段逻辑不闭合；
- 公平检查失败；
- 止损结论为HOLD或FAIL。

以上任一出现，都不进入Day14。
