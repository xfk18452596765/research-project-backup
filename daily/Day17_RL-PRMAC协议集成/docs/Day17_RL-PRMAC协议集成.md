# Day17：RL-PRMAC 协议控制器接入设计

## 1. 当日目标

Day17 只完成接口接入：把 Day14 的本地状态、Day15 的联合动作与本地策略、Day16 的预约段奖励和表格 Q 更新接入 Day13 的 Python 离散事件 Fixed-PRMAC 生命周期。

固定主线保持为：

```text
DCF → Fixed-PRMAC → RL-PRMAC
```

Day17 不开展完整流量训练、不做大规模超参数搜索、不实现 ns-3 RL、不修改固定路由，也不引入中心控制器或全局状态。

## 2. 冻结接口

### 2.1 状态接口

继续使用 Day14：

```text
s = (
    remaining_hops_bin,
    queue_length_bin,
    last_reservation_outcome,
    retry_intensity_bin,
    priority_bin,
    channel_busy_bin
)
```

原始观测全部来自当前预约段起始节点：

- 当前剩余跳数；
- 本地 FIFO 长度；
- 当前业务优先级；
- 本节点上一次预约结果；
- 本节点近期平均重试次数；
- 本节点可获得的信道忙比例。

若当前 Python 模型没有可用的本地 CCA 统计，则继续编码为 `UNKNOWN`，不能伪装成 `LOW`。

### 2.2 动作接口

继续使用 Day15 六动作：

```text
a0=(1,15)
a1=(1,31)
a2=(2,15)
a3=(2,31)
a4=(3,15)
a5=(3,31)
```

动作选择时刻固定为：

```text
本地 FIFO 队首获得服务资格后
→ 初始 DIFS/随机退避之前
```

动作生命周期固定为：

```text
一次初始接入
→ 一个完整预约重试序列
→ 成功后的连续转发和 RELEASE
或重试耗尽失败
```

PR_NACK 后不重新选动作。重试窗口从动作选择的初始 CW 执行 BEB。

### 2.3 奖励和更新接口

继续使用 Day16 奖励公式与 Q-learning 更新，不在 Day17 改权重、归一化尺度、`α` 或 `γ` 的语义。

一次奖励仍对应一个完整预约段：

```text
成功：RELEASE 完成后结算
失败：预约重试耗尽后结算
```

非终止下一状态仍为：

```text
同一节点下一次本地决策时刻的状态
```

另一个节点的决策不能用于更新当前节点 Q 表。

## 3. 分布式控制器结构

Python 离散事件仿真器负责统一执行事件，但逻辑协议仍保持分布式。每个节点独立维护：

```text
LocalNodeAgent = {
    local history,
    SparseLocalQTable,
    LocalEpsilonGreedyPolicy,
    LocalTabularQLearner,
    LocalTransitionAssembler,
    seeded local contention RNG
}
```

不同节点不共享 Q 表、历史、待完成转移或随机数状态。

控制器共享的只有协议常量、动作目录和事件执行设施，不共享节点私有学习值。

## 4. 决策接入点

Day13 原流程在 `_try_start_node_queue()` 中确认本地 FIFO 队首并开始初始接入。Day17 在这里插入：

```text
读取本地观测
→ Day14 状态编码
→ 若本节点有上一条待完成经验，则用当前状态补齐 s' 并更新
→ Day15 ε-greedy 选择合法 (K,CW)
→ 使用所选 CW 进行初始 DIFS/退避
→ 将所选动作绑定到当前预约段
```

该顺序保证上一条 Q 更新先完成，当前决策可以立即使用更新后的本地 Q 值。

## 5. K 和 CW 的真实协议作用

Day17 不通过临时修改全局 `config.fixed_k` 或 `config.fixed_cw_min` 来应用动作，因为多个节点的预约段可能并发运行，修改共享配置会造成串扰。

每个重试序列单独绑定 `SegmentActionDecision`：

- 创建预约记录时，`requested_hops` 和 `effective_hops` 直接取动作 K；
- `K > remaining_hops` 在决策阶段被屏蔽，协议层再次校验；
- 初始接入使用动作 CW；
- 第一次预约尝试记录动作 CW；
- 后续 PR_NACK 使用以动作 CW 为根的 BEB；
- 所有重试尝试继续使用同一个 K。

因此不存在静默截断，也不存在 PR_NACK 后重新选择动作。

## 6. 奖励结算接入

### 6.1 成功

成功结算必须发生在最终 RELEASE 到达预约段端点后，并且要先于本地 FIFO 释放。这样若同一节点队列中已有下一包，它的新状态可以立即作为上一段的 `s'`。

本地奖励输入包括：

- 该段动作与决策时刻；
- 本地排队等待；
- RELEASE 完成时间；
- 实际推进跳数；
- 重试次数和失败尝试数；
- 该包该段产生的 PR_REQ、PR_ACK、PR_NACK、RELEASE、H_ACK 字节；
- 载荷字节；
- 当前段是否完成最终交付；
- 业务优先级。

### 6.2 失败

预约重试耗尽后：

```text
预约序列 FAILED
→ 端到端会话 FAILED
→ 当前段奖励结算
→ 终止转移，bootstrap=0
→ 释放本地 FIFO 服务资格
```

失败奖励不允许报告任何推进跳数。

## 7. 下一状态和显式 episode 结束

非最终成功段结算后，经验暂存在该节点本地。只有同一节点下一次成为预约段起始节点时，才补齐下一状态并执行非终止更新。

若仿真 episode 已结束，但部分节点没有再次获得决策机会，则由仿真外层显式调用：

```text
finalize_pending_learning(reason="simulation_episode_end")
```

该操作只是声明 episode 边界并把本地待完成经验转成终止更新，不向状态注入全局网络信息。

不能在每个数据包结束时无条件清空所有节点经验，因为其他本地业务可能随后继续提供合法的同节点下一状态。

## 8. Day17 新增审计记录

每个预约段建立 `SegmentRLContext`，记录：

- 本地原始观测；
- 离散状态；
- 动作和合法动作集合；
- 重试序列 ID；
- 奖励输入和奖励分解；
- Q 转移；
- Q 更新结果；
- 当前接入状态。

输出中不得包含全网队列、全局 Q 表或中心调度结果。

## 9. 测试边界

Day17 专项测试至少覆盖：

1. Day14—Day16 版本与接口保持不变；
2. 六动作目录保持不变；
3. 节点独立 Q 表；
4. 决策发生在初始 DIFS/退避前；
5. 动作 K 和 CW 真实作用于协议；
6. 非法 K 被屏蔽且不截断；
7. `UNKNOWN` 信道忙状态保留；
8. 成功在 RELEASE 后结算；
9. 最终交付立即执行终止更新；
10. 非最终经验只接受同节点下一状态；
11. 另一个节点不能触发当前节点更新；
12. 同节点下一 FIFO 队首可完成 bootstrap 更新；
13. episode 结束可显式清理本地待完成经验；
14. 优先级同时进入状态和奖励；
15. PR_NACK 后动作保持不变；
16. BEB 从动作 CW 开始；
17. 重试耗尽产生负奖励和终止更新；
18. 队列溢出发生在决策前时不能制造虚假动作；
19. Day13 原有交付与指标继续有效；
20. 输出 JSON 为 UTF-8 且可解析；
21. Day03—Day17 全量回归通过。
