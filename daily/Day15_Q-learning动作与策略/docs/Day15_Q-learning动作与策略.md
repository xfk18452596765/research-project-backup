# Day15：Q-learning动作与策略最终设计

## 1. 仓库继承结论

Day09—Day13 已冻结 Fixed-PRMAC 基线：`K=2`、初始 `CW=15`、`CWmax=1023`，并在每个预约段起点执行 DIFS 与随机退避。Day14 已冻结 1536 个本地离散状态，且明确 Day15 只负责 `(K,CW)`、动作掩码、动作编号和策略。

本日通过新增独立策略模块完成设计，不修改 Day09—Day14 文件，确保 DCF 与 Fixed-PRMAC 回归结果不被 RL 接口污染。

## 2. 为什么最终采用6个动作

项目早期已固定：

```text
K ∈ {1,2,3}
CW ∈ {15,31}
```

该设计表达两类核心权衡：

- `K=1/2/3`：短预约稳健、二跳折中、三跳减少重复竞争；
- `CW=15/31`：激进接入与保守接入。

最终不采用候选原型中的 `K=4` 与 `CW={7,63}`，原因是：

1. 它们不属于原始冻结研究设计；
2. `K=1/2/3` 与后续 Fixed-PRMAC-1/2/3 消融直接对应；
3. 6个动作使单节点稠密表上界为 `1536×6=9216`，更适合当前表格 Q-learning；
4. 先用最小可解释动作集验证“是否存在可学习的状态相关差异”，避免在止损检查前扩张搜索空间；
5. `CW=15` 与既有 Fixed 基线一致，`CW=31` 是其第一阶 BEB 窗口，参数语义与现有代码连续。

## 3. 冻结动作目录

| index | K | initial CW | 含义 |
|---:|---:|---:|---|
| 0 | 1 | 15 | 短预约、激进竞争 |
| 1 | 1 | 31 | 短预约、保守竞争 |
| 2 | 2 | 15 | Fixed-PRMAC 基线 |
| 3 | 2 | 31 | 二跳预约、保守竞争 |
| 4 | 3 | 15 | 长预约、激进竞争 |
| 5 | 3 | 31 | 长预约、保守竞争 |

动作编号使用 K-major、CW-minor 固定顺序，后续日志、Q 表和消融均不得重新排序。

## 4. 决策时刻和动作生命周期

决策发生在：

```text
本地FIFO队首获得服务资格
→ 构造Day14 LocalObservation
→ 编码RLState
→ 选择合法(K,CW)
→ 生成初始DIFS/退避
→ 发起预约
```

一个动作的生命周期覆盖一个完整预约段重试序列：

```text
初始尝试 CW0=action.initial_cw
PR_NACK → retry 1 CW1
再次失败 → retry 2 CW2
……
段成功或重试耗尽 → 动作终止
```

内部 PR_NACK 不重新选动作，否则同一动作的信用边界会被拆散，并与 Day12 已实现的预约重试序列不一致。下一次决策发生在当前段终止后，由下一预约段起点或下一队首分组发起。

## 5. 合法动作掩码

RL 动作必须满足：

```text
K <= remaining_hops
```

合法动作数量：

| remaining_hops | 合法动作数 |
|---:|---:|
| 1 | 2 |
| 2 | 4 |
| ≥3 | 6 |

Fixed-PRMAC 的末段仍可保留 `min(K,remaining_hops)` 兼容逻辑；RL 不使用静默截断，因为截断会让不同动作在末段产生相同实际 K，破坏 Q 值含义。

## 6. CW和BEB语义

动作中的 CW 是该预约段初始窗口：

```text
backoff_slots ~ Uniform{0,...,CW}
```

第 n 次重试（`n=0` 表示初始尝试）：

```text
CW_n = min((CW_initial+1)×2^n-1, 1023)
```

因此：

```text
CW_initial=15 → 15,31,63,127,...
CW_initial=31 → 31,63,127,255,...
```

这与 Day12 的 DIFS、20 μs 槽和 `CWmax=1023` 保持一致。

## 7. 本地策略

每个预约段起始节点拥有：

- 相同的状态编码器；
- 相同的动作字典；
- 独立的 `SparseLocalQTable`；
- 独立、可复现的随机数发生器。

ε-greedy：

```text
概率 ε：在合法动作中均匀探索
概率 1-ε：在合法动作中选择最大Q值
```

若最大 Q 值并列，使用节点本地带种子的随机数打破并列，避免长期偏向低编号动作。

## 8. Day15与后续代码边界

Day15 只提供 Q 值存储和读取，不提供 TD/Bellman 更新。`set_value()` 仅用于初始化和策略测试。

Day16 增加：奖励、转移、学习率、折扣因子和 Q 更新。

Day17 的最小接入点：

1. 在 `FixedPRMACEndToEndController._try_start_node_queue()` 的固定退避生成前构造状态并选动作；
2. 通过 RL 子类或适配器把 `requested_k` 与 `initial_cw` 传入预约/重试序列；
3. 每条段记录保存 `decision_id/state/action/requested_k/effective_k/initial_cw/actual_retry_cw`；
4. Fixed 控制器保持原 `(2,15)` 逻辑和回归结果不变。

## 9. 验收条件

- 动作目录精确为6项且顺序稳定；
- 包含 `(2,15)`；
- 每节点状态—动作上界为9216；
- 合法掩码为2/4/6；

- BEB 从动作 CW 出发并在1023封顶；

- 不同节点 Q 表独立；
- 动作在重试序列内保持不变；
- 不存在奖励、Q更新、训练和中心控制接口；
